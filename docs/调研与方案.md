# 「屏幕取字」工具：调研与开发方案

> 调研日期：2026-10-10 ｜ 目标平台：Windows 10/11（本机 Win11 25H2, build 26200.9457）
>
> 一句话结论：做一个**专注「热键 → 框选 → 本地 OCR → 直接进剪贴板」的常驻小工具**，专攻中文视频场景（抖音/B站的字幕、句子、网址），差异化能力是「视频连拍取字」和「链接/二维码智能处理」，全程本地离线、一步到位。

## 2. 共性与空白分析

**三条 OCR 技术路线各有短板：**

- **系统 OCR（Windows.Media.Ocr）**：快、零依赖，但中文需语言包，且对视频帧（压缩噪点、描边字、低对比度）准确率明显不够（Windrecorder 等项目均有实测吐槽）。
- **本地 PaddleOCR 系（PaddleOCR-json / RapidOCR-json / ONNX）**：中文/视频场景最优解、完全离线，代价是体积与内存——Umi-OCR 用子进程隔离（稳但重），Zshot 用进程内 ONNX + 空闲卸载（轻且快）。
- **云 API / 大模型视觉**：最准，但要联网、有费用与隐私问题，不适合作为默认路径。

**交互范式的空白（我们的机会）：**

1. 现有工具要么是「截图软件 + OCR 功能」（PixPin/Snipaste/Zshot/Text-Grab），要么是「OCR 平台」（Umi-OCR）——**没有一个是"取字专用"的单点工具**，取字动作都不是第一优先级快捷键。
2. **视频场景无人专门优化**：抖音/B站的滚动字幕、弹幕、一闪而过的网址，需要「多帧融合」和「固定区域连续取字」；连 Umi-OCR 都把"固定区域识别"放在远期计划。
3. **输出端粗糙**：普遍不做断行合并、URL 修复与一键打开、二维码解码（视频里常见"扫码关注"）。
4. **一步到位的细节缺失**：识别后焦点不回到原窗口（要再点一下才能 Ctrl+V）、无「重复上次区域」快捷键（视频同一位置连续取字的刚需）。

> 结论：不做第 N 个全能截图工具，做**「屏幕取字」单点极致**——速度、中文视频准确率、智能输出、轻量离线。

## 3. 推荐方案（V1）

### 3.1 定位

> **按一下热键 → 框选 → 文字直接进剪贴板，全程 <1 秒、本地离线。专治视频里的字幕、句子、网址。**

明确非目标（V1 不做，交给 PixPin/Snipaste 等）：标注编辑、贴图钉住、长截图、录屏、跨平台。

### 3.2 技术选型

| 层 | 选择 | 理由 |
|----|------|------|
| 语言 / UI | **C# / .NET 10 (LTS) + WPF** | Windows 原生集成最成熟（托盘、全局热键、多屏 DPI、剪贴板、焦点控制）；有 STranslate、Text-Grab 两个成功先例；开发效率高。本机只有 .NET 6 SDK，需装一次 .NET 10 SDK（winget 几分钟搞定） |
| 屏幕采集 | V1：GDI 拼帧 + PerMonitorV2 DPI（冻结帧）；V1.1：Windows.Graphics.Capture（HDR/独占全屏） | V1 求稳求快，WGC 按 Zshot 路线后续升级 |
| OCR（双引擎） | **主：PP-OCRv5/v6 mobile（ONNX Runtime，CPU）**；备：Windows.Media.Ocr | PP-OCR 模型 ~15MB 随包分发，中文/视频最强且完全离线；系统 OCR 作为纯英文/应急回退，设置里可切换 |
| 扩展（V2 插件） | 云 OCR / 大模型 vision | 满足极限准确率需求，Key 存 Windows 凭据管理器 |
| 关键库 | ONNX Runtime、CommunityToolkit.Mvvm、H.NotifyIcon、ZXing.Net（二维码）、SQLite（历史，M5） | 均为 MIT/宽松许可，可商用 |
| 打包 | 默认 self-contained 单文件（~70–90MB，免装运行时）；另提供 slim 版（依赖运行时，~20MB 含模型） | 自己用省心优先 |

### 3.3 架构（模块划分）

```
SnapText（暂定名）
├─ HotkeyService      全局热键注册 + 冲突检测（默认 Ctrl+Alt+Q；Ctrl+Alt+R 重复上次区域）
├─ CaptureService     多屏虚拟桌面冻结截图（GDI → WGC 演进），记录前台窗口
├─ OverlayWindow      WPF 无边框覆盖层：十字线、放大镜、尺寸提示、选区高亮、Esc/Enter
├─ OcrPipeline
│   ├─ IOcrEngine     ├─ PpOcrOnnxEngine（PP-OCRv5 det/rec/cls，懒加载 + 60s 空闲卸载）
│   │                 ├─ WindowsOcrEngine（系统 OCR 回退）
│   │                 └─ CloudEngine（V2 插件位）
│   └─ Preprocess     2x 放大（小字）、灰度/锐化（可选）
├─ PostProcessor      断行合并（按标点）、中英间距、URL 修复（去空格/合并断行/补协议）
├─ CodeScanner        ZXing.Net 二维码/条形码（一图多码）
├─ ClipboardService   写入剪贴板 + 焦点归还原窗口（可选自动粘贴）
├─ HistoryStore       SQLite 历史 + 搜索（M5）
├─ VideoBurst         连拍取字：多帧 OCR 按行聚类投票（M5，差异化功能）
├─ TrayShell          托盘、设置窗、开机自启、单实例
└─ SettingsStore      JSON 配置（%APPDATA%）
```

**数据流**：热键 → 记录前台窗口 + 冻结全屏 → 覆盖层框选 → 裁剪位图 → 预处理 → OCR → 后处理 → 剪贴板 → 轻提示 toast（含链接则附「打开」按钮）→ 焦点归还原窗口。

### 3.4 关键设计决策

1. **冻结帧**：视频在动，选框时画面会跑——先截后选（微信/QQ 同款交互）。
2. **OCR 会话懒加载 + 空闲卸载**（学 Zshot）：常驻内存 ≤60MB，空闲释放后 ≤40MB。
3. **焦点归还**：复制完成即 `SetForegroundWindow` 回原窗口，用户下一个动作直接 Ctrl+V——"一步到位"的关键细节。
4. **「重复上次区域」热键**：视频字幕位置固定，第二次起单键直接出字（Umi-OCR 同类功能叫"重复上一次截图"）。
5. **文本净化**：OCR 的断行按标点合并（中文不加空格、英文加空格）；URL 去空格、合并被断开的链接、自动补 `https://`。
6. **URL/二维码智能动作**：识别结果含链接 → toast 出现「打开」按钮；二维码解码复用同一通道。
7. **默认静默复制 + 轻提示**：不打断观看；可改为"弹预览窗"或"复制并自动粘贴"。
8. **多屏混合 DPI**：PerMonitorV2 + 每屏独立覆盖层，统一虚拟桌面坐标系（这是最容易翻车的点，M1 就要实测 150%/200% 缩放）。
9. **隐私**：默认零联网；无遥测；云引擎为可选插件。

### 3.5 交互流程（默认路径）

1. `Ctrl+Alt+Q`（可改，带冲突检测）→ 屏幕冻结 + 覆盖层
2. 框选（十字线 + 放大镜 + 尺寸提示；`Esc` 取消；`Enter` 复用上次选区）
3. 松开鼠标即识别（目标 200–600ms）
4. 文字进剪贴板 + 右下角非打扰 toast（含"打开链接"按钮，若有）
5. 焦点自动回原窗口，Ctrl+V 直接粘贴

### 3.6 性能目标（验收基准）

- 热键 → 覆盖层可见：≤100ms
- 框选完成 → 剪贴板：P50 ≤500ms，P95 ≤1s（视选区大小）
- 常驻内存：≤60MB（OCR 会话在），空闲卸载后 ≤40MB
- 中文识别（B站/抖音截帧评测集 20–30 张）字符准确率相对 Windows OCR 提升 ≥15 个百分点（M2 验收门槛，可调）

### 3.8 风险与对策

| 风险 | 对策 |
|------|------|
| 多屏混合 DPI 坐标错位 | PerMonitorV2 + 每屏独立覆盖层；M1 即实测缩放场景 |
| 独占全屏游戏/部分播放器抓不到 | V1 列为已知限制；V1.1 走 WGC 采集（Zshot 同款路线） |
| ONNX 模型装载失败 / 杀软误报 | 模型随包分发 + 哈希校验；发布用 SignPath 免费签名（开源项目） |
| 热键冲突（微信 Alt+A、QQ Ctrl+Alt+A、Snipaste F1、天若 F4） | 默认避开常见键位 + 设置内冲突检测提示 |
| .NET 6 已 EOL、本机无新 SDK | 开发前 winget 安装 .NET 10 SDK（LTS） |
| 识别率不达预期 | M2 量化门槛；预留"高精度模式"（server 模型）与云引擎插件 |

## 4. 实施进度（2026-10-10）

按确认后的方案（C#/.NET + WPF、MVP 闭环、静默复制+轻提示）已完成第一版并可运行，详见项目根目录 `README.md` 与 `dist/SnapText/`。

**已实现**：托盘常驻、全局热键（Ctrl+Alt+Q 取字 / Ctrl+Alt+R 重复上次区域）、多屏冻结帧框选（PerMonitorV2）、PP-OCRv5 本地引擎（RapidOcrNet + 中文模型，随包分发、SHA256 校验）+ Windows OCR 回退、文本净化（中文空格/合行）、剪贴板写入与焦点归还、轻提示、设置窗口、开机自启、脚本化入口（`--grab` / `--grab-region` / `--ocr` / `--capture` / `--bench`）。

**实测（2880×1800，中英混排+网址样张）**：PP-OCRv5 常驻热延迟 p50 ≈ 406ms、网址 100% 正确；Windows OCR ≈ 109ms 但把 `bilibili` 误识为 `biIibiIi`。自动化验收脚本 `tools/smoke-pipeline.ps1` 全绿（截屏→OCR→区域取字→覆盖层；剪贴板项因验证时桌面锁屏而跳过）。

**待办**：M4 智能输出（URL 一键打开 / 二维码）、M5 历史记录 + 视频连拍取字、M6 翻译/云引擎插件；另需在解锁桌面上人工确认一次"热键+鼠标框选"交互。
